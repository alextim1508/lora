# LoRa Bench

Android-приложение (Java) для работы с беспроводными радиочастотными устройствами серии "SHARM" по протоколу LoRa
через BLE (Bluetooth Low Energy). Приложение сканирует BLE-устройства, подключается к одному или нескольким из них
одновременно через GATT/UART, обменивается данными по собственному бинарному протоколу кадрирования и предоставляет
интерфейс с 3 вкладками: мониторинг данных, управление подключением, конфигурация устройства.

Строки интерфейса, сообщения логов и комментарии в коде преимущественно на русском языке.

## Архитектура

Код организован в три слоя в пакете `com.alextim.lora`:

- `client.ble` - транспортный слой BLE для Android (`BluetoothService`). Поддерживает подключение к **нескольким
  BLE-устройствам одновременно**, каждое со своим GATT-соединением и парсером кадров.
- `service.protocol` - логика бинарного кадрирования/парсинга кадров, не зависящая от Android BLE API
  (`BleProtocolParser`, `BleMessageParser` и др.).
- `service` - слой типизированных команд/ответов/событий поверх протокола (`message.BleMessages` и др.),
  `MessageProcessingService` рассылает распарсенные сообщения через `LocalBroadcastManager`.
- `ui` - единственная activity (`BluetoothSetupActivity`) с `ViewPager2` из трех фрагментов: `DataFragment`
  (мониторинг данных), `ConnectionFragment` (подключения), `ManagementFragment` (конфигурация устройства).
  Фрагменты общаются с сервисом через привязку `BluetoothService` и broadcast-сообщения, всегда с ключом
  `EXTRA_DEVICE_ADDRESS` для фильтрации по устройству.

### Поток данных (устройство → интерфейс)

Сырые байты с BLE-характеристики → буфер `BleProtocolParser` устройства → извлечение кадра → `BleMessage` →
парсинг в типизированное сообщение (`BleMessageParser`) → `Intent` через `LocalBroadcastManager` → обновление UI.

### Отправка команд (интерфейс → устройство)

UI формирует `BleMessage` и вызывает `BluetoothService.sendMessage(message, deviceAddress)`, который пишет в
write-характеристику UART нужного устройства. Контрольные суммы считаются автоматически в конструкторе `BleMessage`.

### Поддержка нескольких устройств

Большинство методов `BluetoothService` принимают `deviceAddress`. При добавлении новой BLE-функциональности
следуйте этому паттерну вместо предположения о единственном активном устройстве.
